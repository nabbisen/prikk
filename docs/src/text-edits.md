# Content-Anchored Text Edits

PR-023 introduces a narrow data-model scaffold for future text patches.

The current implementation treats `EditText` as a canonical payload shape only. It is not yet generated by `commit --from-worktree`, and patch replay still rejects it as unsupported. This keeps the later algebra implementation honest: text edits must be based on content anchors and old-span hashes, not byte or line offsets.

Current rules:

- `anchor_id` must be non-empty ASCII without whitespace or control characters.
- `old_span_hash` is exactly 32 bytes.
- The span hash is computed by `text_span_hash(bytes)`.
- Offsets are not part of patch identity or preconditions.

Deferred work:

- anchor discovery from real files
- text diff generation
- text replay
- inverse generation
- commutation and conflict witnesses
