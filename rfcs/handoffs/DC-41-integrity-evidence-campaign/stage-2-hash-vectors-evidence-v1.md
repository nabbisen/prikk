## Vector provenance

| Vectors | Source | Independent verification performed this session |
|---|---|---|
| `""`, `"abc"` | Published (FIPS 180-2 / RFC 6234), pre-existing | Re-confirmed against Python `hashlib` before use as a method check (see below) |
| 56-byte string, 112-byte string | Published (FIPS 180-2 / RFC 6234) | Re-confirmed against Python `hashlib` |
| 55, 56, 63, 64, 65, 119, 120 bytes of `b'a'` | Independently computed | Computed directly with Python's `hashlib.sha256`, **not** with `prikk-hash` |

No expected value was generated by `sha256()` from this crate at any point — every value in
`src/tests.rs` is either a published constant or came from a separate Python process. Before using
`hashlib` to compute the seven boundary vectors, I validated `hashlib` itself against all four published
vectors (`""`, `"abc"`, the 56-byte string, the 112-byte string) — all four matched exactly, which is what
licenses using the same tool for the lengths that have no famous published string. Full verification
command and output:

```
python3 -c '
import hashlib
for length, data, expected in [
    (0, b"", "e3b0c44298fc1c149afbf4c8996fb92427ae41e4649b934ca495991b7852b855"),
    (3, b"abc", "ba7816bf8f01cfea414140de5dae2223b00361a396177a9cb410ff61f20015ad"),
    (56, b"abcdbcdecdefdefgefghfghighijhijkijkljklmklmnlmnomnopnopq", "248d6a61d20638b8e5c026930c3e6039a33ce45964ff2167f6ecedd419db06c1"),
    (112, b"abcdefghbcdefghicdefghijdefghijkefghijklfghijklmghijklmnhijklmnoijklmnopjklmnopqklmnopqrlmnopqrsmnopqrstnopqrstu", "cf5b16a778af8380036ce59e7b0492370b249b11e8f07a51afac45037afee9d1"),
]:
    assert hashlib.sha256(data).hexdigest() == expected
for n in [55, 56, 63, 64, 65, 119, 120]:
    print(n, hashlib.sha256(b"a" * n).hexdigest())
'
```

All four published-vector assertions passed silently (no `AssertionError`); the seven printed digests
match `src/tests.rs` exactly. This reproduces (and independently re-derives, rather than trusts) the
values supplied in the stage-2 handoff.
